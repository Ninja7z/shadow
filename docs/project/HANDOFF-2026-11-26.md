1. Make the terminal experience excellent first. The user wants an installer inspired by Hermes/OpenCode: a single `npm`/`npx` entry point that detects missing prerequisites, installs managed dependencies, guides configuration one step at a time, and ends with useful commands.

3. Web interface / phase 5 is intentionally deferred to the `1.0.0` milestone. It should be optional and local-only initially, started by `web-shadow`, opening a localhost URL that users can click or copy into a browser. Terminal remains fully supported.

## Critical engineering review / next work

The recent clean-rebuild feature is a first pass, not yet proven bulletproof. Before calling it complete, inspect and test:

1. **Interruption matrix:** tests drive the actual installer orchestration through injected external-command fixtures and kill child processes during backup preparation, partial file sync, runtime provisioning and post-commit cleanup. Download-stream failure/timeout and full child-process-tree cancellation are now covered. Run this expanded suite in fresh Linux/Windows/macOS CI, then consider deeper local-HTTP-server tests for real network interruption and a real uv subprocess stub.
2. **Update rollback:** implemented; tests verify restoration, repeated recovery after mid-rollback termination, preservation of private data, and commit-point behavior. Continue with real platform CI and filesystem edge cases before calling it release-grade.
3. **Concurrency:** a cross-platform exclusive lock and conservative stale-lock recovery are implemented; validate on Windows and macOS, including PID reuse and forced termination.
4. **Atomicity:** state writes use temp-file rename; committed/rolled-back states protect against crashes during backup cleanup. Continue testing power-loss/filesystem edge cases.
5. **Preservation tests:** current tests cover `.env`, local config, user data, managed runtime files and `uv`; add full integration tests around provider changes and Ollama files.
6. **Platform correctness:** validate paths, file locks, symlinks, permissions, Python/uv setup, signals and process termination on Linux, Windows, and macOS.
7. **Hash-lock correctness:** verify every Python dependency and transitive dependency is pinned and hash-checked on all target platforms; no silent unpinned fallback.
8. **Failure reporting:** actionable error, safe diagnostics, no API key/secret leakage, and a retry path.
9. **Release quality:** test npm tarball in clean containers/VMs, not only the source checkout.
